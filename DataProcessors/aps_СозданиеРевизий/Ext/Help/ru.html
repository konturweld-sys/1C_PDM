Ревизия — элемент системы PDM, созданный по причине изменения оригинального элемента и хранящий информацию об изменении.

Основой для управляемой структры изделия являются ревизии. Ревизии, подчиняясь определенному правилу управления, замещают в структуре элементы или другие ревизии. При этом логика работы с изделием начинает подчиняться полученной структуре. Чтобы логика не нарушалась, необходима правильная работа с параметрами новой ревизии, которая начинается с корректного создания параметров при создании ревизий. Процесс управления параметрами предполагает четыре вида действий, которые могут произойти с параметрами предыдущей ревизии в момент создания новой:

  • Копирование - в новой ревизии появляется новый параметр, у которого имя, свойство и значение копируются из параметра предыдущей ревизии.
  • Наследование - новый параметр не создается. В новой ревизии используется тот же самый параметр, что и в предыдущей. Изменение праметра в новой ревизии приведет к его изменению в предыдущей и наоборот.
  • Добавление - в новой ревизии появляется новый параметр, который отсутствовал в предыдущей ревизии.
  • Исключение - в новой ревизии параметр предыдущей будет отсутствовать.
Действие для параметра ревизионируемого элемента выбирается в соответствии со способом создания ревизии.

Внимание! Действия над параметрами будут учитываться только для создаваемых ревизий!

Ревизия исполнения – ревизия элемента, созданная при помощи способа создания ревизии «Исполнение». Ревизия исполнения определяет начало новой ветки проектирования изделия, либо фиксации определенной стадии разработки изделия.

Ревизия изменения – ревизия элемента, созданная при помощи способа создания ревизии «Изменение». Ревизия изменения определяет итерацию проектирования изделия в рамках одной ветви проектирования изделия. Идентификатор ревизии изменения уникальный в рамках ревизий исполнения.
